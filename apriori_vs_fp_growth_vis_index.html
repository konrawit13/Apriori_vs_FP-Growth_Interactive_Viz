Metric 1

Support: $P(A \cup B)$

Fraction of total transactions containing both items:

$$\text{supp}(A \Rightarrow B) = \frac{\text{count}(A \cup B)}{N}$$
Filter condition: $\text{supp}(A \Rightarrow B) \ge \text{min\_sup}$
Metric 2

Confidence: $P(B \mid A)$

Likelihood of item $B$ given antecedent $A$ is present:

$$\text{conf}(A \Rightarrow B) = \frac{\text{count}(A \cup B)}{\text{count}(A)}$$
Filter condition: $\text{conf}(A \Rightarrow B) \ge \text{min\_conf}$
Metric 3

Lift: Correlation Ratio

How much more often $A$ and $B$ occur than by independent chance:

$$\text{lift}(A \Rightarrow B) = \frac{\text{conf}(A \Rightarrow B)}{\text{supp}(B)}$$
$\text{Lift} > 1.0 \implies \text{Positive Complementarity}$

Rule Derivation Guide

Educational Architecture: Head-to-Head Comparison

The Apriori Bottleneck

Apriori generates candidate $k$-itemsets ($C_k$) by self-joining $L_{k-1} \bowtie L_{k-1}$. Even with Downward Closure subset pruning, verifying each candidate requires a full disk scan of the transaction database for every iteration $k$.

Passes: $k$ full DB disk scans
Candidates: Combinatorial explosion $\mathcal{O}(2^{|I|})$
The FP-Growth Innovation

FP-Growth compresses transactions into an in-memory Frequent Pattern Tree using exactly 2 database scans. By arranging items in descending frequency, prefixes are highly compressed and mining is done via recursive conditional sub-trees without candidate generation.

Passes: Strictly 2 scans
Candidates: 0 generated (Zero)
Rule Evaluation Metrics
$\text{supp}(A \Rightarrow B) = P(A \cup B)$
$\text{conf}(A \Rightarrow B) = P(B \mid A) = \frac{\text{supp}(A \cup B)}{\text{supp}(A)}$
$\text{lift}(A \Rightarrow B) = \frac{\text{conf}(A \Rightarrow B)}{\text{supp}(B)}$
$\text{Lift} > 1$: Positive Correlation
$\text{Lift} = 1$: Independent Items
